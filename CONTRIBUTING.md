# Contributing to Project SOL

Project SOL is built through respectful collaboration between humans and technology.

## Working rules

- Keep changes small and understandable.
- Use a separate branch for each feature or fix.
- Never commit passwords, private keys, personal records, or confidential information.
- Test on a phone-sized screen and a desktop-sized screen.
- Preserve accessibility: labels, keyboard navigation, contrast, and readable text matter.
- Explain what changed and why in every pull request.
- Update `CHANGELOG.md` for user-visible changes.

## Branch names

- `feature/short-description`
- `fix/short-description`
- `docs/short-description`
- `release/build-###`

## Commit examples

- `feat: add project conversation starter`
- `fix: correct mobile navigation behavior`
- `docs: add GitHub Pages deployment steps`

## Definition of done

A change is done only when it works, is tested, is documented, and can be safely reversed.
